## 🔴 ОТКРЫТЫЕ ПРОБЛЕМЫ

### SND-001 — `AttributeError: 'SmtpAccount' object has no attribute '_lock'`
**Файлы:** `core/models.py`, `core/sender.py`  
**Описание:** Ошибка возникала при любом пути создания `SmtpAccount`, который обходил `__post_init__`:
старый `.pyc` кэш (Python переиспользует bytecode без повторной компиляции),
`copy.copy()`, `pickle`/unpickle, `dataclasses.replace()`. В таких случаях
`_lock`, `_day_reset`, `_hour_reset` не инициализировались.  
**Решение v6.0.5:** Добавлен `__getattr__` safety-net в `models.SmtpAccount` и `sender.SmtpAccount`.
Метод вызывается **только если атрибут отсутствует** (`__getattribute__` уже проверил).
При первом обращении к отсутствующему `_lock`/`_day_reset`/`_hour_reset` — все три
инициализируются атомарно через `object.__setattr__` (нет рекурсии).  
**Статус:** 🟡 ИСПРАВЛЕНО в коде (v6.0.5, commit db435f6f) — ждём подтверждения от пользователя

### SRV-001 — `asyncio.get_event_loop()` в `check_proxies_endpoint`
**Файл:** `core/server.py`  
**Описание:** Вызов `asyncio.get_event_loop()` внутри async-функции — deprecated в Python 3.10+,
вызывал `DeprecationWarning`. В Python 3.12 может подниматься исключение.  
**Решение v6.0.5:** Заменено на `asyncio.get_running_loop()`.  
**Статус:** 🟡 ИСПРАВЛЕНО в коде (v6.0.5, commit db435f6f) — ждём подтверждения от пользователя

## ✅ ЗАКРЫТЫЕ ПРОБЛЕМЫ

### LIC-001 — `IndentationError` в `core/license.py` (КРИТИЧНЫЙ — краш на старте)
**Файл:** `core/license.py`  
**Описание:** Весь файл был с лишним отступом в 2 пробела (начиная со строки 8), что приводило
к `IndentationError: unexpected indent` при импорте. Так как `server.py` импортирует
`core.license` в двух эндпоинтах (`GET /api/license`, `POST /api/license/activate`),
любой вызов этих эндпоинтов падал с 500 Internal Server Error.  
**Воспроизведение:** `python -m py_compile core/license.py` → `IndentationError: unexpected indent (license.py, line 8)`  
**Решение v6.3.1:** Убраны лишние 2 пробела в начале каждой строки файла.  
**Статус:** ✅ ИСПРАВЛЕНО (v6.3.1, автор: code-review agent)  
**Подтверждено:** пользователем не подтверждено — считать ИСПРАВЛЕННЫМ в коде

### PRX-003 — `parse_proxy()` классифицирует HTTP-прокси как `socks5://` (BUG)
**Файл:** `core/proxy.py`  
**Описание:** В ветке `if "@" in raw:` функции `parse_proxy()` прокси формата
`user:pass@host:port` (без явной схемы) получали схему `socks5://` для портов вне
`_HTTP_PORTS` (80, 8080, 3128...). Коммерческие reseller-прокси (порты 10007, 10010,
10011 и аналогичные) всегда используют HTTP CONNECT — их ошибочно классифицировали
как SOCKS5. Результат: SMTP через такие прокси падал с ошибкой SOCKS5-рукопожатия
вместо успешного HTTP CONNECT туннеля.  
**Проверено тестами:** порты 10007/10010/10011 работают через HTTP CONNECT
(220-баннер от smtp.office365.com получен), но `parse_proxy` возвращал `socks5://`.  
**Решение v6.3.1:** Ветка `@` теперь использует `http` как схему по умолчанию.
Явный `socks5://` префикс (от пользователя) по-прежнему работает корректно.  
**Статус:** ✅ ИСПРАВЛЕНО (v6.3.1, автор: code-review agent)

### ACC-SMTP-001 — `5.7.139 SmtpClientAuthentication is disabled` (НЕ БАГ КОДА)
**Аккаунты:** `harrycanoyfvd@outlook.com`, `sevynbennettlmcz@outlook.com`  
**Описание:** OAuth2 refresh токены работают корректно — новые access_token получены.
Однако SMTP AUTH завершается кодом 535 с сообщением
`SmtpClientAuthentication is disabled for the Mailbox`.  
Это **не баг кода** — это настройка уровня Microsoft аккаунта.  
**Причина:** Microsoft по умолчанию отключает SMTP AUTH для новых аккаунтов.
OAuth2 XOAUTH2 также требует включённого SMTP AUTH на стороне аккаунта.  
**Решение (для пользователя):**  
1. Войти в каждый аккаунт на outlook.com  
2. Настройки → Почта → Синхронизация электронной почты  
3. Включить **SMTP AUTH** (POP/IMAP настройки)  
4. Ждать 5-15 минут для применения настроек  
**Альтернатива:** использовать Graph API (не SMTP) для отправки — не требует SMTP AUTH.  
**Статус:** ✅ ДИАГНОСТИРОВАНО — требует действий пользователя (не баг кода)

### PRX-001 — Прокси сбрасываются при перезапуске (только v5 PyQt)
**Файл был:** `gui/screens/screen_accounts.py`  
**Описание:** В v5 глобальные прокси хранились только в памяти (`_SESSION_PROXIES`).  
**Решение:** v6 `core/storage.py` сохраняет прокси на диск в `global_proxies.json`. Поля `proxy`/`proxy_list` при загрузке аккаунтов — сбрасываются (сессионные данные).  
**Статус:** ✅ ЗАКРЫТА (v6 storage.py)

### PRX-002 — Импорт аккаунтов без глобального пула (только v5 PyQt)
**Файл был:** `gui/screens/screen_accounts.py`  
**Описание:** В v5 без прокси — автопроверка не запускалась, неограниченный параллелизм.  
**Решение:** v6 UI (React) — пользователь управляет проверкой через раздел «Аккаунты» вручную или кнопкой «Проверить все».  
**Статус:** ✅ ЗАКРЫТА (архитектура v6)
