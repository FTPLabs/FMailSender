# Скилл: Проверка SMTP через прокси + умное распределение

## Проблема
Прокси может успешно подключаться к HTTP/HTTPS сайтам, но при этом **блокировать SMTP-порты**
(25, 465, 587, 2525) на уровне провайдера. Это ведёт к:
- Молчаливым отказам при рассылке
- "Все аккаунты недоступны" после прокси-теста
- Сожжённым лимитам без единого отправленного письма

## Решение (v4.5.4)

### 1. SMTP-тест при добавлении прокси
`ProxyCheckWorker._check_smtp_via_proxy(proxy_url)` — после базовой проверки
подключается через прокси к `smtp.gmail.com:587` и читает 220-баннер.

Диалог проверки прокси показывает три колонки:
- **Статус** — базовая доступность прокси
- **SMTP :587** — ✓ SMTP / ✗ заблок. — работает ли SMTP через этот прокси
- **Страна**, **Пинг** — метаданные

Только прокси с `✓ SMTP` попадают в `valid_proxies` и назначаются на аккаунты.

### 2. Умное распределение прокси по аккаунтам
`distribute_proxies(accounts, proxies)` в `screen_accounts.py`:
- N прокси на M аккаунтов → round-robin по индексу
- 3 прокси + 30 аккаунтов = по 10 аккаунтов на каждый прокси
- Каждый аккаунт получает `acc.proxy = proxies[i % len(proxies)]` (первичный)
- `acc.proxy_list = proxies` — весь пул для fallback при отправке

При импорте новых аккаунтов: стартовый индекс = `len(existing_accounts)`,
чтобы ротация продолжилась без сброса.

### 3. Инкрементальная проверка
`_test_accounts_by_indices(indices)` — проверяет ТОЛЬКО указанные аккаунты.

После импорта 10 новых аккаунтов к 50 уже проверенным:
- Раньше: `_test_all()` → 60 проверок (бессмысленно)
- Теперь: `_test_accounts_by_indices([50..59])` → 10 проверок

Каждый вызов `_test_single(idx)` с задержкой 50 мс между запусками —
не перегружает очередь воркеров.

### 4. Auth vs Proxy error — три состояния
| Результат | `last_test_ok` | `is_active` | Цвет в таблице |
|---|---|---|---|
| Успех | `True` | `True` | Зелёный «Валидный» |
| Ошибка аутентификации | `False` | `False` | Красный «Невалидный» (скрыт) |
| Ошибка прокси/сети | `None` | без изменений | Оранжевый «Ошибка прокси» |

Ключевые ошибки аутентификации: `"535"`, `"534"`, `"неверный логин"`,
`"неверный пароль"`, `"password"`, `"oauth2 отклонён"`.

## Антипаттерны
- ❌ `is_active = ok` при сбое теста → уничтожает все аккаунты при падении прокси
- ❌ `_test_all()` после импорта → пересчёт всего вместо только новых
- ❌ Использовать прокси без SMTP-теста → молчаливые сбои при рассылке
- ❌ `proxy_list` без выделенного `proxy` → нет приоритета при ротации

## Примеры провайдеров, блокирующих SMTP
- `gw.foxyproxy.online` — публичный шлюз, блокирует все SMTP-порты
- DataCenter прокси часто блокируют порт 25, но разрешают 587
- Residential (резидентные) прокси обычно разрешают все порты
