# Session-Only Data — Данные только для текущей сессии

## Правило

**Прокси** (`proxy_list`, `proxy`, `proxy_list global`) и **список получателей** —
сессионные данные. Они НЕ должны сохраняться на диск и НЕ должны загружаться при
следующем запуске. Пользователь должен импортировать их заново каждую сессию.

**Что сохраняется на диск (постоянные данные):**
- SMTP аккаунты: email, пароль, хост, порт, SSL/TLS настройки
- Лимиты аккаунтов: daily_limit, hourly_limit
- Результат последней проверки: last_test_ok, last_test_msg
- OAuth токены: refresh_token, token_expires_at

**Что НЕ сохраняется (сессионные данные):**
- Глобальный пул прокси (`proxies.dat`)
- Назначения прокси на аккаунты (`proxy`, `proxy_list` в `accounts.dat`)
- Список получателей

## Реализация

```python
# Глобальный пул прокси — in-memory only
_SESSION_PROXIES: list[str] = []

def save_global_proxies(proxies: list[str]) -> None:
    global _SESSION_PROXIES
    _SESSION_PROXIES = list(proxies)  # НЕ пишем на диск

def load_global_proxies() -> list[str]:
    return list(_SESSION_PROXIES)  # НЕ читаем с диска

def save_accounts(accounts):

    # ... сохраняем только email, password, host, port, ...

def load_accounts():
    # НЕ восстанавливаем proxy / proxy_list из JSON
    # ... загружаем только email, password, host, port, ...
```

## Почему это правильно

1. **Безопасность**: устаревшие/заблокированные прокси не используются в следующей сессии.
2. **Предсказуемость**: пользователь контролирует какие прокси активны.
3. **Чистота**: нет накопления мусора в accounts.dat (proxy_list может быть огромным).

## Проверка

При перезапуске приложения:
- Столбец «Прокси» в таблице аккаунтов: пусто / «—» для всех аккаунтов
- Список получателей: пуст (требует повторного импорта)
- Глобальный пул прокси: пуст (кнопка «Импорт прокси» нужна снова)
