# Token Economy Skill — Экономия токенов

## Принципы работы агента

### 1. Принял → Выполнил → Доложил
```
❌ НЕПРАВИЛЬНО:
Agent: "Хорошо, я начну с анализа файла sender.py..."
Agent: "Теперь перейду к smtp_validator.py..."
Agent: "Вижу проблему в строке 142..."
Agent: "Исправил! Теперь проверю..."
Agent: "Готово!"  (5 сообщений = 5x токены)

✅ ПРАВИЛЬНО:
Agent: "Принял задачу, сэр."
[... тихая работа ...]
Agent: "Выполнено. Отчёт: [компактный список]"  (2 сообщения)
```

### 2. Не описывай то что делаешь — просто делай
```
❌ "Сейчас я прочитаю файл gui/screens/screen_accounts.py чтобы понять структуру..."
✅ [читает файл]
```

### 3. Компактные отчёты
```
❌ Длинное описание каждого изменения с кодом до и после

✅ Краткий бюллетень:
• smtp_validator.py:142 — убран PROXY_BLOCKS при таймауте
• screen_accounts.py:89 — добавлен кэш страны прокси
• MAX_CONCURRENT: 10→4
```

### 4. Читай только нужное

```python
# ❌ Читать весь файл 1500 строк чтобы найти одну функцию
read("server/bot.py")  # 120k chars — убивает контекст

# ✅ Сначала grep, потом читать только нужное
grep("def _try_smtp_connect", "core/smtp_validator.py")
read("core/smtp_validator.py", offset=145, limit=50)
```

### 5. Параллельные вызовы инструментов

```python
# ❌ Последовательно (медленно и дорого по токенам)
read(file1)
read(file2)
read(file3)

# ✅ Параллельно (все за один раз)
[read(file1), read(file2), read(file3)]  # один round-trip
```

### 6. Не повторяй известное

Если скилл уже прочитан в этой сессии — не читай повторно.
Если файл уже прочитан — не читай повторно.
Используй knowledge из контекста.

### 7. Формат отчёта (максимально компактный)

```
## Отчёт: [Имя задачи]

**Агент:** [Имя]
**Изменено файлов:** N
**Результат:** OK / WARN / ERROR

Изменения:
• file.py — описание (1 строка)
• file2.py — описание (1 строка)

Проблемы (если есть):
• WARNING: [краткое описание]
```

### 8. Скиллы — читай по необходимости

При старте сессии — читай ТОЛЬКО скиллы нужные для текущей задачи.
Не загружай все 52 скилла если задача касается только GUI.

### 9. GitHub API — батчи

```python
# ❌ Отдельный API вызов на каждый файл
for file in files:
    create_blob(file)  # N API вызовов
    update_tree(file)
    
# ✅ Все файлы в одном дереве
blobs = await Promise.all(files.map(create_blob))  # параллельно
create_single_tree(blobs)  # один вызов
```

### 10. Не проси подтверждения на очевидные действия

```
❌ "Мне нужно прочитать файл smtp_validator.py. Разрешите?"
✅ [читает файл]
```

## Метрики

Хорошая сессия: ≤ 3 сообщения на задачу (принял → работа → доложил)
Плохая сессия: > 10 сообщений на простую задачу
